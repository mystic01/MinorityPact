- 保留預約再次決策與訊息訂閱喚醒：到期取得最新授權資訊，再決定是否發言。
- 保留窗口機制；同批決策不參考同批新行動。UI按實際batchId分組，取消自動逐席播放，點選頭像或公開訊息切換閱讀焦點。

- 新局交涉上限90秒遊戲時間；舊局保留原設定。messageTiming未指定時沿用舊版scheduled，新局明確使用immediate。
- 使用者確認D行為合理，保留自主沉默及停止訂閱，不實作強制喚醒或強制施壓。

## 本次D沉默調查

唯讀檢查最新本機對局，至第4回合、總遊戲時間130000ms：D累計15份完成決策，其中公開發言4則、私訊3則；其餘席位公開發言A21、B10、C18、E22則。D多次交涉回覆僅set_ready或空actions，並非所有沉默都由API失敗造成。先前第3回合確有HTTP429，後續已有成功結果；查詢時狀態為paused，無pending決策。

其他席位已公開催促D確認，包含以未來輪替利益說服。D在125000ms公開訊息自稱C，決策快照agentId與原始模型回覆的所屬席位均為D；130000ms又自稱D。這是模型輸出身分混淆的證據，不足以判定刻意欺騙，也未發現程式將C輸出掛到D的證據。不得自動改寫已存訊息。

喚醒紀錄確認：D在第2回合20000ms及第3回合65000ms的nextWake均為onEvents:[]且無指定時間，因此後續訊息不會喚醒它，直到強制階段切換才再次呼叫。這是目前允許模型自行停止監聽的行為，會造成其他人催促而D無法及時重新決策的產品問題。

同局已存決策含88個未來排程的訊息行動，顯示預排確實被使用，不能假設訊息送達時間等於思考時間。此數字不是已送達訊息數，可能包含後續取消者。

## 建議，尚未核定為規則

- 對每席明確重申自身身分、個人奪冠目標與機器計算的計分規則，避免跟隨其他發言的自稱或錯誤算術。
- 加入客觀公開活動摘要及自上次決策後的新事件，協助辨認誰尚未公開回覆；不把沉默推論成拒絕，也不洩漏ready、私訊正文或技術故障。
- 引導模型判斷本次發言是否新增資訊；允許等待、針對未解問題詢問或修改提案，避免自動反覆重申。不得指定必須施壓D或導演衝突。
- 評估直接點名訊息的喚醒規則；目前取消訂閱的席位不一定收到下一次即時決策機會。任何新規則應全席一致，而不是只對D強制呼叫。
- 發言品質需區分身分混淆、規則理解、重複確認及自主策略；單局無法證明模型整體能力。
