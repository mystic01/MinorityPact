# 契約付款內部規格（管理者用，禁止送入玩家提示詞）

本文件保存使用者明確指定的隱藏規則。玩家文件為 CONTRACTS.md；不要把本文件、伺服器結算程式或本節規格放入 AI 快照。

## 支付能力

逐付款人彙總本輪已成立、未解除且條件已觸發的契約。未觸發、未接受及已解除契約不占額度。支付能力為原有累積總分加本輪原始選色獎金，絕不包含本輪收到的契約付款。

若某付款人應付總額超過支付能力，該人本輪所有已觸發付款全部歸零，每份通知原因皆為「付款人支付能力不足」。不按比例支付、不挑選先付哪份、不建立欠款。剛好足額則全部支付；某人的失敗不影響其他付款人。付款總額使用 BigInt 比較，避免多份大額承諾合計超出安全整數而誤判。

例：A 原有零分、本輪獎金三分，對 B、C 分別觸發兩分付款，總額四分，因此都不付。若 A 原有一分則可支付四分，兩份各付兩分。若 B 的條件未觸發，僅 C 的兩分計入總額，照常支付。

所有付款人以相同的付款前基準同時判斷，禁止用其他付款人的入款補足本輪額度。先計算原始獎金與觸發條件，再計算所有契約實付與分數淨額。對外只發一次合併後的 scores_updated，保留原始少數勝次；個別契約結算是雙方私有事件。即使實付全為零，也不會額外向第三人發出契約存在的通知。

## 持久化與相容

contractsEnabled 為凍結於本局的設定；未帶此欄位的舊局不啟用契約。新局範本預設啟用，網頁可關閉。事件完整保存契約狀態與通知，重啟與回放透過 reducer 還原；每輪開始清空前輪操作狀態，歷史事件仍保留。無須更改 SQLite 表結構。

提案者固定為付款人，接受者固定為收款人，不能代第三人簽署或解除。協定使用當前邏輯時間；參照操作必須指向批次開始前已存在的契約，無效引用產生僅發給操作人的拒絕通知。契約事件不向不相關玩家公開，終局全知重播沿用既有完成門檻。

## 驗證

tests/contracts.test.ts 包含雙人確認、多約、大額承諾、禁止單方解除、同批隔離、門檻不足／剛好足額、僅觸發條件計額、入款不補額度、三類條件、總分與勝次、舊局隔離、隱藏規則未進提示詞、通知喚醒、落盤重啟及完整五回合腳本局。

tests/contracts-browser.ts 使用離線腳本代理驗證真人介面、接受、私人通知、雙方解除及公開投影；不呼叫付費 API。這些是系統行為驗證，不代表真實模型已發現隱藏規則。
