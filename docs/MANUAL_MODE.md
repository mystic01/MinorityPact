# 手動檔案模式（網頁自動檢查）

## 開始

執行 `npm.cmd start`，開啟 http://127.0.0.1:3000。在「新對局」將「AI 連接方式」選為「手動檔案（自動檢查回覆）」，建立後按「開始對局」。不需要 API key，此模式不呼叫 OpenRouter。

網頁顯示資料夾 `data/manual/對局ID/` 與各席狀態。只有 AI 席位有 Markdown 檔案，真人席位在網頁操作；歷史備份另存 archive。

## 每次只要複製貼上

1. 開啟網頁列為「等待回覆」的 player-A.md 等檔案。
2. 全選檔案、複製，直接貼給該玩家的 AI。**不用另加任何說明**。每席使用獨立對話；建議每次開新對話，檔案已有必要上下文。
3. 將 AI 的完整 JSON 答案貼回同檔最下方 `<!-- RESPONSE_START -->` 與 `<!-- RESPONSE_END -->` 之間。保留標記及其餘內容，以 UTF-8 儲存。
4. **不用按 Enter 或匯入按鈕**。後端每秒檢查一次，內容連續兩次相同才讀取，網頁自動顯示等待、儲存穩定、驗證失敗或已接受。
5. 本批需要的 AI 回覆全部合法，且真人（若有）已提交後自動結算並更新下一批提示詞。重新開啟最新檔案再重複操作。未被喚醒的玩家顯示「本批無需回覆」；一回合可能包含多次交換。

每份檔案包含完整規則、該席可見歷史與分數、當前階段專用 JSON Schema、請求編號與修正要求。AI 必須輸出 requestId 與 decision，不用你手動組合 JSON。

格式或編號錯誤會顯示在網頁，原檔保留讓你補貼。遊戲規則驗證失敗時會備份原檔並產生附修正要求的新檔；重新開啟最新版本，整份交給 AI 修正。已接受的回覆會鎖定，之後修改檔案不改變該決策。若編輯器提示外部檔案已變更，請重新載入，不要以舊分頁覆蓋新提示詞。

## 暫停、續接與保存

網頁「暫停」停止後續檢查，「繼續對局」恢復。關閉網頁不會停止後端，請先暫停。伺服器重啟後選擇原對局並按「繼續對局」，已接受結果與待處理快照仍保存在資料庫。

等待人工操作不消耗遊戲時間，同批回覆不提前互相公開。資料庫沿用伺服器設定（預設 data/games.sqlite），交換檔位於 data/manual。不要刪除資料庫或交換檔；這些檔案含私訊與策略，保留在已忽略的 data 目錄。

外部 AI 由你選擇，系統不驗證其真實模型身分，存檔標示「手動檔案（外部模型未驗證）」。可選五 AI 觀戰，或選一席由真人參與、其餘四席使用手動檔案。原 OpenRouter 模式仍可使用；離線測試不代表真實模型策略驗收。

## 契約付款

新局可啟用雙人契約。每席提示檔會附上操作規則、可用行動與本人契約通知；依原有方式複製貼上即可。只有系統通知成立才生效，聊天承諾不算接受。詳見 [契約操作](CONTRACTS.md)。

## 真人加入手動模式

「AI 連接方式」選手動檔案後，「參與方式」仍可選 A～E 任一真人席位。真人沿用 API 模式的公開發言、私訊、契約、準備投票與秘密選色介面，不需要填寫 Markdown。例如真人是 A，只會產生 player-B.md 至 player-E.md 四份。

真人與 AI 皆可先提交；先提交的內容鎖定，同批不提前公開。進度區將真人顯示為「你（網頁操作）」與「等待你提交／你已提交」，AI 顯示檔案狀態。真人提交且該批所需 AI 回覆齊全才結算；未喚醒的 AI 不需補交。真人仍以「提交並推進」控制五秒邏輯窗口，等待不消耗遊戲時間。

重新整理後可看到已提交狀態；伺服器重啟後按「繼續對局」，保留真人提交、部分 AI 結果與原快照。開局後不能更換真人席位，既有五 AI 對局不會被改成真人對局。

## 更新後出現建立失敗

若手動模式選真人後無法建立，先在原伺服器啟動視窗按 Ctrl+C，待程序退出後重新執行 start-game.bat，再重新整理網頁。更新前端檔案不會重新載入已執行中的 Node 後端。新版會偵測手動真人支援能力並顯示重啟提示；啟動器也會在 3000 埠已被占用時停止，避免新畫面連到舊後端。此錯誤不需要補 API key。
